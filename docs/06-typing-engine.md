# タイピング入力エンジン

`packages/shared` に置き、フロントの打鍵判定とバックエンドの打鍵数計算の両方で使う。

## ローマ字の柔軟性

1つの仮名に複数のローマ字表記を受け付ける。

**判定の流れ**

1. かな→ローマ字を1対多の候補配列で保持する
2. 1文字打たれるたび、現在の入力文字列に前方一致する候補だけに絞り込む
3. 候補のいずれかと完全一致した時点で、そのかなを確定して次へ進む

### 対応する表記の揺れ

**子音の揺れ**

| かな | 候補 |
|---|---|
| し | `shi` / `si` / `ci` |
| ち | `chi` / `ti` |
| つ | `tsu` / `tu` |
| ふ | `fu` / `hu` |
| じ | `ji` / `zi` |
| ぢ | `di` |
| づ | `du` |

**拗音（ようおん）は3系統ある**

| かな | 候補 |
|---|---|
| しゃ / しゅ / しょ | `sha`・`sya` / `shu`・`syu` / `sho`・`syo` |
| ちゃ / ちゅ / ちょ | `cha`・`tya`・`cya` / `chu`・`tyu`・`cyu` / `cho`・`tyo`・`cyo` |
| じゃ / じゅ / じょ | `ja`・`zya`・`jya` / `ju`・`zyu`・`jyu` / `jo`・`zyo`・`jyo` |
| きゃ・にゃ・ひゃ・みゃ・りゃ 等 | `kya` / `nya` / `hya` / `mya` / `rya`（1系統のみ） |

**拗音の分解入力にも対応する**

`きゃ` を `ki` + 小書きの `ゃ` として打つ人がいる。候補文字列を足すだけで対応できるため、対応する。

| かな | 追加する候補 |
|---|---|
| きゃ | `kixya` / `kilya`（`kya` に加えて） |
| しゃ | `sixya` / `silya` / `shixya` / `shilya` |
| （他の拗音も同様） | `<子音部の候補>` + `xya`・`lya` の組み合わせ |

**小書き文字を単体で打つ場合**

| かな | 候補 |
|---|---|
| ぁ / ぃ / ぅ / ぇ / ぉ | `xa`・`la` / `xi`・`li` / `xu`・`lu` / `xe`・`le` / `xo`・`lo` |
| ゃ / ゅ / ょ | `xya`・`lya` / `xyu`・`lyu` / `xyo`・`lyo` |

**外来語のかな**

お題にカタカナ語が含まれるため、読み仮名にこれらが現れる。対応しないと打てなくなる。

| かな | 候補 |
|---|---|
| ふぁ / ふぃ / ふぇ / ふぉ | `fa` / `fi` / `fe` / `fo` |
| てぃ / でぃ | `thi` / `dhi` |
| うぃ / うぇ | `wi` / `we` |
| ゔ | `vu` |

## 「ん」「っ」の扱い

実行時にバックトラックしないよう、**候補テーブルを組み立てる時点（次の仮名を先読みできる状態）で確定させる。**

| かな | ルール |
|---|---|
| `っ` | 次の仮名の子音候補を借用する（次が「た」行なら `t`）。加えて `ltu` / `xtu` / `ltsu` |
| `ん` | 常に `nn` / `xn` が使える。加えて、次が子音始まりの仮名なら `n` 単体も可（次が母音・や行・文末の場合は `n` 単体を認めない） |

`xn` はIMEの対応表にある正規の打ち方なので、文脈を問わず受理する。

`n` 単体を母音の前で認めないのは、`ん`+`あ` が `na` となり「な」と区別できなくなるため。HENGEはお題のテキストを知っているので技術的には解決できるが、**IMEで通用しない打ち方を許容しない**方針に合わせる。

IMEが許容する全パターンの完全再現は狙わない。曖昧さを設計時点で排除する。

> **Phase 6で確認すること**: 「ん」の直後が「な行」の場合に `n` 単体を認めるか。参考にした対応表には「な行の前では `nn` が必要」とあるが、実際には `minna` で「みんな」が打てるなど、常用される打ち方と食い違う。実機で確認して決める。

## 記号

対応するのは `、` `。` `ー` `！` `？` の5種。候補は1つずつで揺れがない。

| 記号 | キー | Shift | 打鍵数 |
|---|---|---|---|
| `、` | `,` | 不要 | 1 |
| `。` | `.` | 不要 | 1 |
| `ー` | `-` | 不要 | 1 |
| `！` | `1` | **必要** | 1 |
| `？` | `/` | **必要** | 1 |

- `,` `.` `/` `-` の位置はJIS配列とUS配列で共通のため、この5種に限れば配列差を考慮しなくてよい
- **Shiftは打鍵数に数えない**（`！`は2キー押下だが1打として計上）

## キーボード表示

**4段＋Shift**（数字段・QWERTY3段・両端のShift）。アルファベット3段では `！`（Shift+`1`）、`？`（Shift+`/`）、`ー`（`-`）が打てない。

### ハイライトが複数キーに及ぶ2つの意味を区別する

| 場面 | 例 | 意味 | 表示 |
|---|---|---|---|
| ローマ字の候補違い | `ふ` → `F` と `H` | **どちらか一方**を押す | 同じ強さで並列に光らせる |
| 修飾キーとの組み合わせ | `！` → `Shift` と `1` | **両方同時**に押す | 修飾キー側を別扱いにする |

同じ見た目にすると確実に誤解を招く。

## IME対策

**タイピング判定に `<input>` や `<textarea>` を使わない。** `<div tabindex="0">` などフォーカス可能な非編集要素へのkeydownで実装する。

IMEは「編集可能な要素にフォーカスがある」ことをトリガーに変換処理を始める。入力欄が存在しなければIMEは介入せず、**ひらがな入力モードのままでも押されたキーがそのまま渡ってくる**。

ブラウザ・OS・IME製品（Microsoft IME、Google日本語入力など）の組み合わせで実機検証すること。

**モバイル（画面キーボード）は対象外。** 物理キーボード前提の設計であり、画面キーボードはこの方式では解決しない。

## テスト

このエンジンはD1/KVに依存しない純粋な関数なので、**`bun test` で書く**（Vitestは不要）。

最低限カバーすべきケース:

- 複数候補の受理（`fu`/`hu` どちらでも「ふ」が確定する）
- 前方一致の絞り込み（`s` を打った後に `h` と `i` の両方が候補に残る）
- `っ` の子音借用（`いって` を `itte` で打てる）
- **`ん` の3通り**（`nka` / `nnka` / `xnka` がいずれも「んか」になる）
- **`ん` の文脈判定**（`んあ` に `na` を使えない。`nna` / `xna` のみ）
- **拗音の3系統**（`sha` / `sya` のどちらでも「しゃ」が確定する）
- **拗音の分解入力**（`kixya` / `kilya` で「きゃ」が確定する）
- **外来語のかな**（`fa` で「ふぁ」、`thi` で「てぃ」）
- 記号5種のマッピング
- 打鍵数の計算（10〜40の境界値）。**候補が複数ある場合は最短の候補で数える**
