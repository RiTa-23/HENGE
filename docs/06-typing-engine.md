# タイピング入力エンジン

`packages/shared` に置き、フロントの打鍵判定とバックエンドの打鍵数計算の両方で使う。

## ローマ字の柔軟性

1つの仮名に複数のローマ字表記を受け付ける。

**判定の流れ**

1. かな→ローマ字を1対多の候補配列で保持する
2. 1文字打たれるたび、現在の入力文字列に前方一致する候補だけに絞り込む
3. 候補のいずれかと完全一致した時点で、そのかなを確定して次へ進む

### 画面に出す打ち方

**`table.ts` の候補の並びが、画面に出す打ち方の優先順。** 未確定のかなは先頭の候補で表示する（`し` → `si`、`ち` → `ti`、`つ` → `tu`、`しゃ` → `sya`、`ちゃ` → `tya`。`じ` → `ji`、`じゃ` → `ja`、`ふ` → `fu`）。新しいかなを足すときは、既定にしたい打ち方を先頭に置く。

**「っ」と次のかなは揃える。** かなごとに選ぶと、`っ` は `chi` 由来の `c`、`ち` は `ti` になり、`まっち` が `macti` と出る。

- 未確定の `っ` は、次のかなの表示の頭文字を重ねる（`まっち` → `matti`）
- `っ` を子音1文字で打ち終えていたら、次のかなはその子音で始まる候補を出す（`mac` と打てば `macchi`）
- 別の候補で打ち始めれば、残った候補に表示が切り替わる（`s` `h` と打てば `shi`）
- **打鍵数は並びに関係なく最短の候補で数える**（下の「テスト」）

**かな単位で表示の打ち方を指定できる**（`startTyping(units, chosen)` の `chosen`。かなの添字 → 打ち方）。最適化練習で、利用者が選んだ打ち方（`し` を `shi`）を的の箇所に出すために使う（`docs/07-ui.md`「最適化の運指」）。

- **表示だけを変える。** 受理する候補は変わらない。指定が残っている候補に無ければ（その箇所で打てない打ち方・別の経路で打ち始めた）、上の既定の選び方に戻る
- 前の `っ` は指定した打ち方の頭文字に揃う（`っち` に `chi` を指定すれば `cchi`）
- 苦手キーの集計（`missedKeys`）も、画面に出していた打ち方の文字で数える

**表示は実行時に `table.ts` を見て決める**（`match.ts` の `DISPLAY_RANK` / `displayOf()`）。保存済みの候補配列（`reading_roman_json`）の並びには頼らないので、**並べ替えただけなら既存のお題を作り直さなくてよい。** `rebuild:roman` も並びだけの違いは書き直さない（下の「書き込みの量に気をつける」）。

### 対応する表記の揺れ

**子音の揺れ**

| かな | 候補 |
|---|---|
| し | `si` / `shi` |
| ち | `ti` / `chi` |
| つ | `tu` / `tsu` |
| ふ | `fu` / `hu` |
| じ | `ji` / `zi` |
| ぢ | `di` |
| づ | `du` |

候補は表示の優先順に並べている（先頭が既定の表示。上の「画面に出す打ち方」）。

**拗音（ようおん）は3系統ある**

| かな | 候補 |
|---|---|
| しゃ / しゅ / しょ | `sya`・`sha` / `syu`・`shu` / `syo`・`sho` |
| しぇ | `sye`・`she` |
| ちゃ / ちゅ / ちょ | `tya`・`cha`・`cya` / `tyu`・`chu`・`cyu` / `tyo`・`cho`・`cyo` |
| じゃ / じゅ / じょ | `ja`・`zya`・`jya` / `ju`・`zyu`・`jyu` / `jo`・`zyo`・`jyo` |
| きゃ・にゃ・ひゃ・みゃ・りゃ 等 | `kya` / `nya` / `hya` / `mya` / `rya`（1系統のみ） |

**拗音の分解入力にも対応する**

`きゃ` を `ki` + 小書きの `ゃ` として打つ人がいる。候補文字列を足すだけで対応できるため、対応する。

| かな | 追加する候補 |
|---|---|
| きゃ | `kixya` / `kilya`（`kya` に加えて） |
| しゃ | `sixya` / `silya` / `shixya` / `shilya` |
| （他の拗音も同様） | `<子音部の候補>` + `xya`・`lya` の組み合わせ |

**小書き文字を単体で打つ場合**

| かな | 候補 |
|---|---|
| ぁ / ぃ / ぅ / ぇ / ぉ | `xa`・`la` / `xi`・`li` / `xu`・`lu` / `xe`・`le` / `xo`・`lo` |
| ゃ / ゅ / ょ | `xya`・`lya` / `xyu`・`lyu` / `xyo`・`lyo` |

**外来語のかな**

お題にカタカナ語が含まれるため、読み仮名にこれらが現れる。対応しないと打てなくなる。

| かな | 候補 |
|---|---|
| ふぁ / ふぃ / ふぇ / ふぉ | `fa` / `fi` / `fe` / `fo` |
| ふゃ / ふゅ / ふょ | `fya` / `fyu` / `fyo` |
| じぇ / ぢぇ / ちぇ | `je`・`zye`・`jye` / `dye` / `tye`・`che`・`cye` |
| てぃ / でぃ | `thi` / `dhi` |
| てゅ / でゅ | `thu` / `dhu` |
| とぅ / どぅ | `twu` / `dwu` |
| つぁ / つぃ / つぇ / つぉ | `tsa` / `tsi` / `tse` / `tso` |
| くぁ / くぃ / くぇ / くぉ | `qa`・`kwa` / `qi`・`kwi` / `qe`・`kwe` / `qo`・`kwo` |
| ゔ / ゔぁ / ゔぃ / ゔぇ / ゔぉ | `vu` / `va` / `vi` / `ve` / `vo` |
| うぁ / うぃ / うぇ / うぉ | `wha` / `wi`・`whi` / `we`・`whe` / `who` |

**族（同じ子音の並び）ごとにまとめて持つ。** 1つだけ足すと、隣り合うかなが分解入力（`うぉ` に対する `uxo` / `ulo`、`ゔぁ` に対する `vuxa`）でしか打てないままになり、**かなごとに打てる打ち方が違う**という覚えられない状態になる。

**単独のかなが両方あっても、組み合わせが表に無ければ分解入力しか残らない。** `ゔ`（`vu`）と `ぁ`（`xa`）が揃っていても、`ゔぁ` が無ければ `splitKanaUnits()` は2単位に割り、「ヴァンパイア」は `vuxa` でしか打てない。**打てなくはない**ので画面を見ても気付けない壊れ方で、`typing.test.ts` に実在の外来語の読みで機械的に見るテストを置いている。

### 何を表に持つか

**共通語彙リスト（`vocabulary.generated.ts` の28,703語）の読みに現れるかで決める。** 小書きのかな（`ぁぃぅぇぉゃゅょゎ`）が後ろに来る2かなを全部数え、現れた組とその族を持つ。現れない族（`ぐぁ`=`gwa`・`いぇ`=`ye`・`すぃ`=`swi`・`てゃ`/`てぇ`/`てょ`・`ゔゅ`=`vyu`）は足さない。読みの辞書には固有名詞も入っているので「グァム」のような語がお題に出ることはありうるが、そのときも分解入力では打てる。**出てきたら足す**（IMEの全パターンを先回りで並べない、という上の方針どおり）。

## `table.ts` を変えたら、既存のお題を作り直す

**ローマ字候補はお題を作った時点で計算して、D1へ焼き込んでいる**（`prompts.reading_roman_json`）。
プレイ中に `buildRomanCandidates()` は呼ばれず、保存済みの配列をそのまま使う。

つまり **`table.ts` に打ち方を足しても、既存のお題には遡及しない。** 「ちぇ」を足しても、
それ以前のお題は `ち` + `ぇ` に分解されたまま保存されていて、`che` では打てない。

`table.ts` を触ったPRでは、必ずこれを流す。

```bash
bun run rebuild:roman -- --remote            # 下見（書かない）
bun run rebuild:roman -- --remote --apply    # 書き込む
```

**読み仮名はD1にあるので、読み Worker は叩かない。** `buildRomanCandidates()` は純粋関数で、
全部ローカルで完結する。`reading_roman_json` と `keystroke_count` は必ず一緒に作り直す
（片方だけ直すと、画面に出る打鍵数と実際の打鍵数が食い違う）。

### 書き込みの量に気をつける

**D1の書き込みは1日10万行で、使い切るとその日はD1へのクエリが全部落ちる**（＝アプリが止まる）。
復旧はUTC 0時のリセット待ちで、こちらから戻す手段はない。

そのため、このスクリプトは**いまの値と違う行だけ**を書く。**かな1単位の中の候補の並びは比べない**（表示は実行時に `table.ts` の並びで決めるので、並べ替えだけで全行を書き直さない）。`table.ts` の変更はふつう一部のかな
にしか効かないので、実際の書き込みはほぼゼロになる。5,000行を超える場合は `--force` が要る。

大量に書く日は、先に残り枠を見る。`--limit=` で分けて流せる（何度流しても同じ結果になる）。

```bash
bunx wrangler d1 info henge-db               # rows_written_24h を見る
bun run rebuild:roman -- --remote --apply --limit=5000
```

### 勝手に消さない

次の2つは**報告するだけ**で、消すかどうかは人が決める。

| 状態 | 扱い |
|---|---|
| `table.ts` からかなを消して、もう組み立てられない | **書き換えない。**打てないお題として一覧に出す |
| 作り直した結果、打鍵数が**その形式の範囲**（短文10〜35／単語4〜20）の外に出た | **書き換えはする**（古い値も同じだけ間違っている）。一覧に出す |

## 「ん」「っ」の扱い

実行時にバックトラックしないよう、**候補テーブルを組み立てる時点（次の仮名を先読みできる状態）で確定させる。**

| かな | ルール |
|---|---|
| `っ` | 次の仮名の子音候補を借用する（次が「た」行なら `t`）。加えて `ltu` / `xtu` / `ltsu` |
| `ん` | 常に `nn` / `xn` が使える。加えて、次が子音始まりの仮名なら `n` 単体も可（次が母音・や行・文末の場合は `n` 単体を認めない） |

`xn` はIMEの対応表にある正規の打ち方なので、文脈を問わず受理する。

`n` 単体を母音の前で認めないのは、`ん`+`あ` が `na` となり「な」と区別できなくなるため。HENGEはお題のテキストを知っているので技術的には解決できるが、**IMEで通用しない打ち方を許容しない**方針に合わせる。

IMEが許容する全パターンの完全再現は狙わない。曖昧さを設計時点で排除する。

**「ん」の直後が「な行」の場合、`n` 単体は認めない。** `n`+`な` が `nna` となり「んな」と衝突するため。IMEによっては `minna` で「みんな」が打てるが、HENGEでは受理しない（`minnna` / `mixnna` のみ）。母音・や行の前で `n` 単体を認めないのと同じ理由で、曖昧さを設計時点で排除する方針を優先する。

## 記号

対応するのは `、` `。` `ー` `！` `？` の5種。候補は1つずつで揺れがない。

| 記号 | キー | Shift | 打鍵数 |
|---|---|---|---|
| `、` | `,` | 不要 | 1 |
| `。` | `.` | 不要 | 1 |
| `ー` | `-` | 不要 | 1 |
| `！` | `1` | **必要** | 1 |
| `？` | `/` | **必要** | 1 |

- `,` `.` `/` `-` の位置はJIS配列とUS配列で共通のため、この5種に限れば配列差を考慮しなくてよい
- **Shiftは打鍵数に数えない**（`！`は2キー押下だが1打として計上）

## キーボード表示

**4段＋Shift**（数字段・QWERTY3段・両端のShift）。アルファベット3段では `！`（Shift+`1`）、`？`（Shift+`/`）、`ー`（`-`）が打てない。

### 光らせるのは画面に出ている打ち方の1文字だけ

ローマ字の候補違い（`し` で `S` の次に `H` と `I`）は、**巻物に出ている打ち方の次の1文字だけ**を光らせる（`romanDisplay()` の苦無の位置の文字）。候補それぞれの次の1文字を全部光らせると、画面の表記と違うキーまで光ってどれを押せばよいか迷う。別の候補で打っても受理はされ、打った経路に表示が切り替わるので、光るキーもそれに従う。

複数のキーが光るのは**修飾キーとの組み合わせ**（`！` → `Shift` と `1`）だけで、**両方同時**に押す意味になる。修飾キー側は破線にして別扱いにする。**光らせる Shift は押すキーと反対側の1つだけ**（`！` は右、`？` は左）。反対の手の小指で押すのがタッチタイピングの運指で、プレイ画面の運指ガイドもそう出す（`docs/07-ui.md`「運指ガイド」）。

**次に打つキーは橙、打ち間違えたキーは赤。** 色の決め方と理由は `docs/07-ui.md`（配色・忍者モチーフ）に置く。ここに書くと2か所で管理することになる。

## `KeyboardEvent.key` の正規化

**`event.key` をそのまま `pressKey()` に渡さない。** 候補テーブルは**小文字のASCII**しか持たない（`a`〜`z` と `! , - . ?`）ため、素通しすると次が起きる。

| 届く `key` | 原因 | 素通しした場合 |
|---|---|---|
| `"S"` | **Caps Lock**、または Shift 併用 | 候補 `si` に一致せず**ミス**。正しく打っているのに1文字も進まない |
| `"し"` | IMEが日本語入力のまま | 同上 |
| `"Shift"` `"Enter"` | 名前付きキー | 1文字でないので従来から無視される |

変換は `packages/shared` の `normalizeTypedKey()` に閉じ込め、画面側は戻り値だけを渡す。

- **大文字は小文字に倒す。** Caps Lock でも Shift でも同じ結果にする（`！` は Shift+`1` で `key` が `"!"` として来るのでそのまま受ける）
- **打鍵として解釈できないキーは `null` を返し、ミスに数えない。** 「解釈できない」と「打ち間違えた」は別物で、混ぜると正確率が壊れる
- `isImeKey()` が真のとき（`"Process"` やかな・漢字）は、画面に**「英数入力に切り替えてください」**と出す。黙って無視すると、利用者には「打っても何も起きない」としか見えない

この壊れ方は**画面から原因が一切見えない**（正しいキーを押しているのに全部ミスになる）ため、`packages/shared/src/typing/input.test.ts` に、正規化を外すと大文字が全打鍵ミスになることを再現する回帰テストを置いている。

## IME対策

**タイピング判定に `<input>` や `<textarea>` を使わない。** `<div tabindex="0">` などフォーカス可能な非編集要素へのkeydownで実装する。

IMEは「編集可能な要素にフォーカスがある」ことをトリガーに変換処理を始める。入力欄が存在しなければIMEは介入せず、**ひらがな入力モードのままでも押されたキーがそのまま渡ってくる**。

ブラウザ・OS・IME製品（Microsoft IME、Google日本語入力など）の組み合わせで実機検証すること。

**検証済み: macOS。** ひらがな入力モードのままでも打鍵がそのまま渡ってくることを確認した。**Windows（Microsoft IME）は未検証。** Phase 8 の動作確認までに実機で確認する。

**モバイル（画面キーボード）は対象外。** 物理キーボード前提の設計であり、画面キーボードはこの方式では解決しない。

## テスト

このエンジンはD1/KVに依存しない純粋な関数なので、**`bun test` で書く**（Vitestは不要）。

最低限カバーすべきケース:

- 複数候補の受理（`fu`/`hu` どちらでも「ふ」が確定する）
- 前方一致の絞り込み（`s` を打った後に `h` と `i` の両方が候補に残る）
- `っ` の子音借用（`いって` を `itte` で打てる）
- **`ん` の3通り**（`nka` / `nnka` / `xnka` がいずれも「んか」になる）
- **`ん` の文脈判定**（`んあ` に `na` を使えない。`nna` / `xna` のみ。な行の前も同様に `n` 単体は不可）
- **拗音の3系統**（`sha` / `sya` のどちらでも「しゃ」が確定する）
- **拗音の分解入力**（`kixya` / `kilya` で「きゃ」が確定する）
- **外来語のかな**（`fa` で「ふぁ」、`thi` で「てぃ」、`who` で「うぉ」、`va` で「ゔぁ」）。**実在の外来語の読みに、分解されたままの小書きのかなが残らないこと**も機械的に見る
- 記号5種のマッピング
- **`event.key` の正規化**（`"S"` が `s` として通る／かなと名前付きキーはミスに数えない）
- **苦手キーの集計**（`missedKeys`。打つべきだった文字を数える／候補が複数なら画面に出ている候補で数える）
- **表示の候補**（未確定のかなは `table.ts` の先頭。保存済みの並びには頼らない。`っち` は `tti`、`っ` を `c` で打てば `cchi`。`chosen` で指定した打ち方は、候補に残っているときだけ出す）
- 打鍵数の計算（10〜35の境界値）。**候補が複数ある場合は最短の候補で数える**
